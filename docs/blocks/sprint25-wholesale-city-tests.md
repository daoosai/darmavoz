# Спринт 25: город оптовой модерации и регрессионные проверки

## Назначение и работа
AdminWholesaleScreen подписан на useOperatorCityStore.cityId. Список передаёт
city_id вместе с view/status/q/page; пустой город означает общий режим.
Смена города сохраняет статус/поиск, сбрасывает страницу и карточку деталей,
отменяет предыдущий запрос. Поздний ответ и ошибка предыдущего города
не меняют текущий список. Обновление вручную также отменяет прежний запрос.

## Ключевые файлы
- frontend/src/AdminWholesaleScreen.tsx; GET /api/v1/wholesale-requests.
- frontend/tests/e2e/sprint24.spec.ts: город, общий режим, пагинация, задержанный ответ.
- frontend/tests/e2e/sprint24_25.spec.ts: действующие pending/approved,
  отправка на модерацию, кабинет админа, возврат в Опт через навигацию,
  корзина 100 м³ и выбор кнопки машины по accessible name.
- frontend/tests/e2e/sprint25.spec.ts: убрано ожидание скрытого PUSH-индикатора.
  Начальная авторизация не перезаписывает текущую роль; переходы между ролями
  в Sprint24 меняют localStorage явно, без зависимости от порядка init scripts.
- tests/test_dispatch_volume_matching.py: категория заказа/машины/варианта
  доставки, смена, действующие данные допуска.
- tests/test_sprint25_api.py: реальный worker в savepoint-сессиях внутри
  rollback-only транзакции; чужая тестовая очередь восстановлена откатом.
- .github/workflows/deploy-test.yml: Sprint25 API/unit, volume и smart matching,
  UI Sprint24/25/совместные; прежние Sprint22 проверки сохранены.

Старые тесты за согласованным объёмом перечислены в отдельном
[отчёте](../2026-10-05-deferred-legacy-tests.md).
