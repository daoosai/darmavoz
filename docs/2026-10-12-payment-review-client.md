# Whitelist клиента ЮKassa — 12.10.2026

Поручение: backend-only изменение в develop и main, тестовый и боевой контуры. Версии приложения и серверные .env не менять.

Добавлено точное исключение +79999999999 / 0000 в клиентской авторизации. SMS-провайдер не вызывается; профиль Client создаётся стандартным путём при первом входе, существующий профиль используется повторно. verify-code поддерживает повторный вход без challenge и отклоняет другие коды. Общий SMS-service не менялся: production USE_REAL_SMS=true не принимает 0000 для остальных номеров, test USE_REAL_SMS=false сохраняет общий sandbox 0000 по явному уточнению владельца.

Read-only аудит до изменений подтвердил активный Client с этим номером в обеих БД; создавать/переименовывать его вручную не нужно. На тесте также есть активный User-driver с таким же sub и auth_version. Обнаружено, что get_current_user не разделял client/employee JWT при совпадении sub; добавлено отклонение токенов с role=client/client_id, чтобы исключение давало только клиентский доступ. Google Play reviewer с 7777 и сотруднические SMS-ручки сохраняют штатную логику.

Проверки: первоначальный целевой набор из 40 тестов прошёл; добавлены регрессии совпадающего сотрудника и отсутствия bypass общего OTP, итог и доставка будут записаны после завершения. npm run lint успешен. flake8 E9/F63/F7/F82/F401 для затронутых Python-файлов успешен; flake8 установлен только в одноразовом контейнере, зависимости репозитория не менялись.

Production-данные, реальные SMS на обычные номера и платёж не отправляются при проверках. После деплоя требуется проверить внешние send-code/verify-code, роль/профиль клиента, отсутствие сотруднического доступа, негативный 0000 для другого production-номера и сохранение тестового sandbox. Каталог/корзина/переход к оформлению проверяются без создания реального заказа/платежа. Ограничения доступности предложений фиксируются отдельно от логина.
