# Отмена клиентом до загрузки и ручной возврат — 19.10.2026

Контур: develop, /opt/darmavoz_test, test.darmavoz.ru.
UI и API прежде запрещали отмену уже с driver_accepted.
Граница перенесена на loading: раньше него отмена доступна, включая
arrived_at_pickup (также расположен до loading).

Ранние статусы сохраняют полный автоматический возврат.
driver_accepted/heading_to_pickup/arrived_at_pickup показывают предупреждение
в модалке причины и при подтверждении отменяют заказ с ручным решением по возврату.
Водитель освобождается, предложения отменяются, назначения очищаются.
Платёж, его сумма/статус/финансовые флаги не трогаются; Refund не создаётся;
провайдер не вызывается. Сотрудническое уведомление содержит refund_mode=manual.
Повтор отмены не создаёт финансовых операций. Поздняя оплата и ручной частичный
возврат не запускают автоматически возврат остатка, поскольку auto intent не установлен.

Файлы: frontend/src/OrdersScreen.tsx; app/api/clients.py;
app/services/refunds.py; tests/test_refunds.py; client-order-card.spec.ts.
Миграций, изменений .env, версии и production нет.
Регрессии: платёжные ветви/водитель/повторы/сверка/ручной остаток и UI
на 390/1440 px, подтверждение и отказ, граница loading.
Проверки на ноде: npm run lint — pass; tests/test_refunds.py — 43 passed;
client-order-card + client-refund-info — 56 passed (390/1440 px).
Все платежные тесты в отдельной disposable PostgreSQL с mock ЮKassa;
браузерные регрессии используют API-фикстуры. Скриншот предупреждения
heading_to_pickup на 390 px визуально проверен. Коммит/доставка фиксируются далее.
