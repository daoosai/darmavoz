# Клиентская карта: диагностика и восстановление — 14.10.2026

Контур: develop / test.darmavoz.ru. Пользователь сообщил старый текст
«Для отображения карты требуется поддержка WebGL…».

До изменений реальная 2ГИС на опубликованном сайте загрузилась на 1440/390px:
WebGL=true, SDK=true, 10 маркеров, карта визуально просмотрена. HTTP ошибок
картографического сервиса не было. Исходный сбой на устройстве пользователя
не воспроизведён: браузер/устройство пока не указаны.

Воспроизведён отдельный подтверждённый дефект: при блокировке SDK карта
объявляла отсутствие WebGL; после восстановления сети и повторного открытия
карты загрузка SDK не повторялась (sdkAttempts=1, SDK=false, fallback=true).
Причина: один rejected promise сохранялся на всю сессию, а обработчик
ожидал load/error уже завершившегося HTML script.

Исправления описаны в blocks/client-map.md. Разделены причины ошибок,
добавлен retry, сбрасывается кеш неудачной загрузки, очищаются ресурсы.
Используется SDK isSupported, пробный GPU-контекст legacy проверки освобождается.
Не менялись backend, .env, ключи, номера версии и production.

Проверки на ноде:
- npm run lint — успешно.
- npm run build — успешно.
- global-map-location.spec.ts + map-recovery.spec.ts — 9 passed.
  Первый dev-прогон без VITE_2GIS_KEY выявил отсутствие ключа в dev mode.
  Повтор выполнен с qa-mocked-only, SDK подменяется; .env не менялись.
- Проверены SDK failure → retry без reload на 390/1440px, различение
  WebGL/ошибки constructor, повторное создание карты, GPS/отказ/адрес.
- Реальная диагностика до изменений:
  docs/reports/2026-10-14-map-diagnostic/diagnostic.json и скриншоты рядом.
