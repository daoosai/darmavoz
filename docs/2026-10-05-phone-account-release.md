# Освобождение номера для водителя — 05.10.2026

Контур: test.darmavoz.ru, develop; production не затронут.
Номер, указанный владельцем, занимал активный User с ролью supplier;
Driver с этим номером и Driver с user_id этого аккаунта отсутствовали.
Поэтому отсутствие записи в списке водителей не означало свободный логин:
_ensure_unique_driver_phone проверяет drivers.phone и users.username.
Сообщение DRIVER_PHONE_ALREADY_EXISTS в данном случае неточно: конфликт
был с аккаунтом поставщика, а не с существующим водителем.

После явного подтверждения владельцем удаления поставщика выполнено
удаление доступа и архивирование аккаунта: is_deleted=true, is_active=false,
логин переименован, профильные поля/FCM очищены, auth_version повышен,
зафиксированы deleted_at/deletion_source. Точка и пять оптовых заявок
сохранены; физическое удаление связанных бизнес-данных не выполнялось.

Проверка на фактической БД: ни users.username, ни drivers.phone не занимают
номер и его стандартные варианты; _ensure_unique_driver_phone проходит.
Нового фиктивного водителя для проверки не создавали.
Браузер/Playwright не запускали. Код приложения и .env не меняли;
операция применена к БД немедленно, пересборка не требуется.

Общее поведение удаления водителей не менялось этой операцией:
DELETE /admin/drivers/{id} пытается физически удалить Driver/User,
при препятствующих FK сохраняет архив с освобождённым телефоном.
DELETE /drivers/{id} выполняет деактивацию; это отдельная существующая
логика, не причина конфликта данного номера.
