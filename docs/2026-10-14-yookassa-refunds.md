# 14.10.2026 — автоматические и ручные возвраты ЮKassa

Контур: /opt/darmavoz_test, develop; доставка только в test.darmavoz.ru.
Утверждённые PO/Tech Lead правила реализованы, основной блок: [refunds](blocks/refunds.md).

## Изменения

- Отмена и долговечное обязательство возврата записываются атомарно без вызова
  ЮKassa; очередь переживает недоступность интеграции и перезапуск воркера.
- Поздний succeeded после разрешённой отмены также возвращается. waiting_for_capture
  закрывается отменой авторизации. Исторические отмены без признака обязательства
  автоматически не обрабатываются.
- Балансы возвращённого/зарезервированного/доступного остатка рассчитываются
  отдельно от Payment.status. Сериализация Order → Payment → Refund через
  with_for_update(), уникальность незавершённой операции и request_id.
- Сохранённые body/key до POST, повтор по тому же ключу, backoff, остановка
  неопределённого POST после 23 часов, резерв сохраняется до сверки.
- Ручной полный/частичный возврат admin/logist с суммой, обязательной причиной,
  подтверждением и историей. HTTP 202 означает очередь, не завершение возврата.
- Проверяемые через API webhook refund.succeeded, импорт внешних частичных
  возвратов, дедупликация событий и периодическая сверка локальных операций.
- Чеки частичных возвратов с точным распределением копеек; после частичного
  возврата чек зачёта на остаток. Неопределённый чек зачёта блокирует возврат.
- Hard Delete финансовых заказов запрещён, независимо от статуса платежа и
  возврата. Финансовый заказ в реестре архивируется с сохранением истории.
  Нефинансовые заказы, в том числе с одной только ценовой котировкой, удаляются.

## Передача QA

1. Новый тестовый оплаченный заказ отменить клиентом до heading_to_pickup:
   cancelled сразу, возврат queued, затем succeeded; деньги/статус возврата
   сверить в sandbox кабинете.
2. Повторить с ручным частичным возвратом, затем отменой: возвращается только
   остаток, суммарно не больше оплаты.
3. Временно недоступная ЮKassa: отмена успешна, задача остаётся; после восстановления
   возврат завершается. Неизвестный результат никогда не повторять новым ключом.
4. Проверить настоящую доставку refund.succeeded из кабинета и чек возврата.
   Mock-тесты и ручная доставка webhook не доказывают доставку из кабинета.
5. Исторические отменённые заказы остаются для ручного решения. Не запускать
   массовые возвраты при проверке этой поставки.

Обычный переход водителя driver_assigned → heading_to_pickup закрывает клиентскую
отмену. Отдельный статус driver_accepted также уже заблокирован сервером.
Границы отмены этой задачей не менялись.
