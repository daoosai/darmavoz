# Отдельная админская модерация и черновики оптовых заявок — 02.10.2026

Контур: /opt/darmavoz_test, develop; test.darmavoz.ru/app. Production не меняется.

Причина дефекта: AdminDashboard монтировал полноэкранный партнёрский WholesaleScreen
через CommerceShell. Он закрывал общий header/sidebar, показывал создание и
партнёрские вкладки, а действия модерации прятал в деталях.

Реализация:
- AdminWholesaleScreen встроен в штатный AdminDashboard: белая шапка,
  NotificationCenter и существующее выдвижное левое меню остаются доступными.
  Переходы из sidebar, общей модерации, профиля и уведомлений ведут в этот экран.
- Только фильтры pending/approved/rejected/archived/all, поиск и пагинация.
  Pending-карточки содержат крупные зелёную «Одобрить» и красную «Отклонить».
  Reject использует общий ReasonModal, пустая причина запрещена; решения сохраняет
  существующий moderate API с уведомлением автора. Детали и история доступны.
- API view=moderation&status=... только для admin; чужие pending/rejected не
  открываются партнёрам через фильтр. Черновики исключены даже из admin all.
- У поставщика «Отправить на модерацию», «Сохранить черновик», «Предпросмотр».
  POST/PUT ?draft=true сохраняют статус draft без уведомления администрации;
  обычное сохранение отправляет pending и создаёт inbox/PUSH outbox админа.
  Черновик виден только автору в «Мои заявки»; «Редактировать» предзаполняет форму.
  Поля формы сохраняют текущую валидацию, черновик сохраняется с заполненными
  обязательными данными. Черновик можно сохранить повторно или отправить.
- WholesaleOut и карточка поддерживают draft/«Черновик».
  Миграция s24_wholesale_drafts расширяет constraint без изменения прежних заявок.
  Существующие запросы без draft сохраняют прежнее поведение.

Проверки перед delivery: npm run lint и build; backend pytest
tests/test_sprint24.py + tests/test_sprint24_api.py (53 passed), одноразовая БД.
E2E покрывают меню/шапку, отсутствие партнёрских действий, прямую модерацию,
причину, статусные фильтры на 320/390/768/1440 и цикл draft->edit->pending.
Первый полный запуск: 30 passed; 4 новых проверки потребовали уточнить locator
повторяющегося заголовка админки. Итоговый адресный результат и live-delivery
фиксируются в docs/reports/wholesale-admin-view-live.json на ноде.
Этот отчёт создаётся после push/CI без дополнительного коммита документации.

Физическая FCM-доставка на устройство отдельно не проверяется; inbox и
транзакционный outbox покрыты API-тестами. Версии приложения/.env не изменяются.
