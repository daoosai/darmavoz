# HTTPS и доступность каталога

Оба контура обслуживает общий контейнер `daoos_kit-caddy-1`. Live-конфигурация: `/opt/daoos-kit/configs/Caddyfile`, `sites/darmavoz.caddy`, `sites/darmavoz-test.caddy`. API проксируется на `darmavoz_backend:8000` и `backend_test:8000`. Хранилище сертификатов — Docker volume `daoos_kit_caddy_data`, каталог `caddy/certificates/`.

При Failed to fetch сначала проверить внешний HTTPS, состояние и логи Caddy, затем внутренние `/health`, `/api/v1/catalog/materials/` и `/api/v1/catalog/calculator/`. Пустой JSON метаданных действующего сертификата препятствует запуску Caddy даже при целых CRT и KEY. Перед восстановлением делать защищённую резервную копию, проверять срок, домен и соответствие ключа; не копировать приватные ключи в Git.

10.10.2026 восстановлены пустые метаданные обоих доменов, сертификаты и ключи сохранены; подтверждены API и браузерный каталог/калькулятор во всех трёх размерах экрана. Приложение не изменено. Подробности, ограничения и проверки: [отчёт восстановления](../2026-10-10-https-recovery.md).
